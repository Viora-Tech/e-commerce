# Admin design system (Proofly look)

The admin follows the Figma file "Vextro admin" (Foundations and Components pages). The tokens
live in `packages/ui/src/styles.css`; only the admin imports that file, so the storefront is not
affected. Variable names match the Figma code syntax (`var(--key-top)`, `var(--raised)`).

## Rules

- **One blue.** `--primary` (#3F72DC light, #7FA2F5 dark) with opacity tints only (`--primary-soft`).
  `--action` is the same blue. A member's own accent pick still overrides `--primary*` at runtime.
- **Fonts.** DM Sans for every UI string. Bricolage Grotesque only for page titles and big
  numbers: the `text-page-title`, `text-stat` and `text-kit-stat*` utilities switch to it.
  Both load through `next/font/google` in `app/layout.tsx`.
- **Layers.** Shell (`--sidebar`, top bar) below the content panel (`--background`) below cards
  (`--card`) below raised surfaces (`--raised`: menus, toasts, floating bars). Dark mode is
  layered the same way, never flat black.
- **Key material** (gradient, top highlight, bottom lip, soft glow) is for the one primary action
  on a screen and main header actions only. Use `<Button>` (key-primary, the default variant) or
  `<Button variant="key-neutral">`. Everything small is `outline` (plain-outline) or `ghost`
  (plain-ghost). `loading` shows the spinner and blocks presses.
- **Status chips** (`components/layout/status-chip.tsx`) are coloured only when someone has to
  act; done states are neutral grey with a hairline.
- **Radius.** 16 for the content panel, 12 for cards, 10 for controls, 8 for chips.

## siteConfig

`packages/config/src/site.ts` (import `@commerce/config/site`) holds the platform name, tagline,
domain, logos, support contact, public URLs, locale defaults (INR, en-IN, Asia/Kolkata), UI
defaults (rows per page 10/25/50/100, toast times), plan-limit placeholders and social links. It
is pure data with no secrets, so client code may import it. The `site-config` sweep fails on the
literal brand name anywhere else.

## Routes

`apps/admin/src/lib/routes.ts` is the one list of admin URLs (`routes.orders.detail(id)`,
`routes.settings.taxes()`). Navigation data, the command palette and the shell read from it. The
`admin-routes` sweep fails on a new hardcoded admin href; the allow-list counts per file and may
only go down.
