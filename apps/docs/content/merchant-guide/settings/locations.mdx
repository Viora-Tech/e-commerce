# Locations & warehouses

**Settings → Locations & warehouses** lists every place you keep stock: your default location and
any warehouses you added under **Stock → Inventory**, in the order orders are sent from them.

## What this is for

- Seeing which GST number each location bills under.
- Spotting a location in a state where you have no GST number yet.
- Choosing which warehouses send online orders, and in what order.
- Letting couriers collect parcels from the warehouse that sends them.

## How it works

- Each row shows the location, its state and **Bills under**: the GST number used for orders
  sent from there.
- A warning such as *"No GST number for Delhi yet"* means the location is in a state where you
  have not added a GST number. If you send orders from there, you usually need one. Add it on
  [GST numbers](/merchant-guide/settings/taxes#gst-numbers-tab).
- Open a location to choose **Bills under**. Only GST numbers from that location's own state
  can be picked, because goods leaving a state are billed under that state's GST number.
- A location without a state can use any GST number. Add its address under **Stock →
  Inventory** to get the state check.

Orders whose products sell from a location are billed from its GST number: its state decides
CGST + SGST or IGST, and its invoices carry that GST number. Your prices include GST, so the
shopper pays the same either way. A location with no GST number chosen bills from your default
one.

### Sending orders from more than one warehouse

The **Online orders** column says whether a location **Ships** online orders or keeps **Stock
only**. Your default location always ships. Open another location and turn on **Ships online
orders** to let orders be sent from its stock; its stock then counts toward what your store shows
as available.

When a customer orders, the order is sent from one location that has everything, picking the
customer's own state first, then the order of the list (use the arrows in **Order** to change
it). If no single location has everything, the order is split into parcels from more than one
location, never more than **Most parcels per order** under **How orders are sent** (2 unless you
change it). Each parcel is billed by its own location's GST number and gets its own invoice; the
customer still sees one order and pays the same.

If an order would need more parcels than you allow, your default location sends the rest even
though it does not have it all. That parcel shows **Needs stock moved** on the order page: move
the stock there before you pack it. An order is only refused when all your locations together do
not have enough.

A location whose GST number is on the composition scheme never sends to another state (the law
does not allow it). If only such a location has the item, a customer in another state sees *"We
can't deliver this item to your state yet."*

The order page shows where each part goes from under **Ships from** (or **Ships in 2 parcels**):
each parcel's location, its GST number, its items and how many are packed.

Your customer is told too, before paying and after: when an order will split, checkout shows
**Ships in 2 parcels** under the delivery choice, with each parcel's items, the city it comes from
and its expected delivery dates (your courier's estimate from that warehouse). The same list is on
the thank-you page, the order page in their account and the order confirmation email. An order
that ships in one parcel looks exactly as before.

### Courier pickup

Each row also shows **Courier pickup**: either the location's own address, or **Return address
in Shipping settings** (what every store uses until it turns this on).

Open a location and use **Courier pickup** to turn on **Couriers pick up from this address**.
Couriers then collect parcels for orders sent from this location here, and returns come back
here too. Fill in:

- **Pickup name at your courier**: the pickup location name exactly as it is on your Delhivery
  or Shiprocket dashboard. Leave it empty to use the one saved in the courier app.
- **Contact name** and **Phone**: printed on labels. Empty uses the location's name and phone.

The location needs a full address (line 1, city, state and PIN code) first. Turn the switch off
and save to go back to the return address in **Settings → Shipping**.

### Local delivery and pickup in store

Open a location to offer two more delivery options at checkout, beside your shipping prices:

- **Local delivery**: you deliver yourself. List the **PIN codes you deliver to** (`560038`, or
  `5601*` for every code starting 5601), the **Delivery price**, an optional **Minimum order**
  and **Free above** value, and **Delivery instructions** (like "We deliver between 4 and 8
  pm"). Shoppers in those PIN codes see "Local delivery from Indiranagar".
- **Pickup in store**: shoppers collect the order here, free. Add a **Pickup time** ("Usually
  ready in 2 hours") and **Pickup instructions**; both show under the option at checkout.

The order keeps which location and option the shopper picked. Hand these orders over yourself
and mark them fulfilled; no courier is booked for them.

### Split shipping

**Settings → Shipping → Split shipping** lets one order ship in several shipments when no single
location has every item. Off, every order ships in one parcel. On, it can split into up to the
number of parcels set under "Sending orders from more than one warehouse".

## Try it

1. Open **Settings → Locations & warehouses**.
2. Open a location and pick a GST number under **Bills under**. It saves straight away.
3. Try a location in a state with no GST number: you see the warning and an **Add a GST
   number** button.
4. On a location with a full address, turn on **Couriers pick up from this address**, type the
   pickup name from your courier dashboard and select **Save pickup**.
5. Open a second warehouse and turn on **Ships online orders**. Back on the list, move it up with
   the arrows and set **Most parcels per order**.
6. Place a test order for two items that sit in different warehouses: the order page shows
   **Ships in 2 parcels**, one from each.
