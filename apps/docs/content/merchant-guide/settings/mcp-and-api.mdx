# MCP & API

**Settings → MCP & API** lets AI apps work with your store. You can ask Claude about yesterday's
orders, or let Cursor read your products while it builds a theme. Each app acts as the person who
connected it, so it can never do more than that person's role allows. It can use every action the
admin has, from fulfilling an order to editing a theme. Changes run straight away with that
person's role, unless their role has that action on **Ask first** (see
[Staff & roles](/merchant-guide/settings/staff#off-allowed-and-ask-first)): then it waits in
**Settings → Approvals**. Refunds, cancellations, deletes and money, staff, billing and domain
settings always wait for a person to click in the admin, even when the owner connected the app.

The page reads top to bottom:

1. **Status:** how many AI apps are connected (or **Not connected yet**), when the last request
   came, and your store's **MCP server URL** with a copy button.
2. **Connect an AI app:** a step-by-step guide for each app.
3. **Connected AI apps:** every app that is connected right now.
4. **Permissions & approvals:** the rules in plain words, and two switches.
5. **API tokens:** tokens for scripts, servers and apps that cannot sign in.
6. **Activity:** a link to everything apps and tokens did.

Every store has its own MCP server URL. Connections belong to the address you used: if you
connected an app to your live admin, it shows on your live admin's page.

## Connect an AI app

Open **Settings → MCP & API** and pick your app under **Connect an AI app**. Every app uses the
same server URL. The first time it connects, the app opens a sign-in page: sign in with your
account, choose the areas it may use (products, orders, customers, inventory, discounts, content,
analytics, marketing, online store and settings, each as **Read** or **Read & write**) and click
**Allow**.

### Claude (claude.ai and Claude Desktop)

1. Copy the server URL.
2. On claude.ai, open **Settings → Connectors → Add custom connector**. Paste the URL and name
   it after your store. The connector also shows in Claude Desktop and the mobile app.
3. Claude opens the sign-in page. Choose the areas and click **Allow**.

### Claude Code

1. In your terminal, run the command the page shows, for example:

   ```bash
   claude mcp add --transport http koomerce https://admin.example.com/api/mcp/your-store
   ```

   Add `--scope user` to use it in every project.
2. Start Claude Code, type `/mcp`, pick the server and choose **Authenticate**. Your browser
   opens the sign-in page.
3. Ask something like "What sold yesterday?"

### ChatGPT

ChatGPT works with the server: it speaks Streamable HTTP with OAuth sign-in, which ChatGPT's
developer mode needs.

1. In ChatGPT, open **Settings → Apps & Connectors → Advanced settings** and turn on
   **Developer mode** (paid ChatGPT plans).
2. Click **Create**, paste the server URL and pick **OAuth** for authentication.
3. Sign in and click **Allow**. ChatGPT also asks you to confirm each change before it sends it.

### Cursor and VS Code

Click **Add to Cursor** or **Add to VS Code**, or paste the config the page shows into
`~/.cursor/mcp.json` (Cursor) or `.vscode/mcp.json` (VS Code). The app asks you to sign in the
first time it uses the server.

### Other MCP apps

The page shows a config with the server URL (transport: Streamable HTTP) and, for apps that only
run local servers, an `mcp-remote` config that bridges to it. Apps that support MCP sign-in open
the sign-in page on their own.

### Using an API token instead of signing in

Some apps cannot open a sign-in page. For those, click **Create API token** in the guide, then send
the token with every request:

```text
Authorization: Bearer YOUR_API_TOKEN
```

The guide shows the Claude Code command and the config for each app with the header filled in, and
the token's dialog shows them with your real token. A token's changes happen at once, without
approval, so prefer signing in when the app supports it.

Web apps such as claude.ai and ChatGPT reach your store from their own servers, so they need your
public admin address. On a test copy that runs on your own computer the page says so; use Claude
Code, Cursor or VS Code there.

## What AI apps can do

A connected app gets three kinds of tools:

- **Quick reads** such as `findProducts`, `orderDetails`, `salesSummary` and `lowStock` answer
  straight away.
- **Proposals** such as `proposeProductUpdate`, `proposeDiscount` and `proposeCollection` make a
  change straight away with your role (or send it to Approvals when your role needs approval).
- **Every admin action:** `searchActions` finds an action, `describeAction` shows its inputs and
  whether it waits for approval, and `runAction` runs it.

The rules, in plain words: reads run right away; changes run with the connecting person's role,
and wait in **Settings → Approvals** when that role needs approval for them; sensitive actions
always wait for a person in the admin; and an app can never sign in as you, create or revoke
tokens, or approve its own changes.

If you connected an app before this update, reconnect it (or restart it) so it loads every action.

## Connected AI apps

The list shows every app that signed in and every API token that has been used:

- **App:** the name the app gave when it connected (for example "Claude", "Claude Code" or
  "Cursor"), and how it connects: **Signed in with OAuth** or **API token**.
- **Connected by:** the person it acts for, their role, and the date.
- **Can do:** the areas it can read and change.
- **Last used:** when it last made a request.

Click **Disconnect** (or **Revoke** for a token) and confirm. It stops working right away. Changes
already waiting in AI approvals stay there. Disconnect anything you don't recognise, and anything
belonging to someone who left your team.

If an app has not been used for 30 days, its sign-in lapses and the list says **Sign-in lapsed**;
connect it again from the app.

## Permissions & approvals

The card first says, in plain words, what happens right now:

- Reads run right away.
- Changes run at once with the connecting person's role (or wait in Approvals when their role
  needs approval for them), or are off.
- Sensitive actions always wait for a person in the admin.
- Whether apps can read customer details.

Two switches apply to every app that signs in. Click **Save** after changing them.

| Switch | On | Off |
|---|---|---|
| **Allow AI apps to make changes** | Apps can use any admin action your role allows, in the areas you ticked | Apps can only read |
| **Let apps read customer details** | Apps can see names, phone numbers and addresses | Off by default; orders still show the city |

### Sensitive actions always wait

Some actions always wait for a person to click in the admin, even when the owner connected the
app and even when the role does not need approval: refunds and store
credit, cancellations, anything that deletes or removes, gift card balances, payment gateway keys
and payment settings, staff, roles and invitations, billing and your plan, domains, deleting or
exporting the store, and the MCP & API settings themselves. An app can never sign in as you,
create or revoke tokens, or approve its own changes.

### Approving a change

When an app suggests a change, the activity log shows a row like "Claude proposed: …, waiting
approval".

1. Click **Open approval** on that row.
2. You see the same preview the AI bar shows: what changes, before and after. For any other admin
   action you see its name, what it does, and every value the app sent.
3. Click **Approve**, **Edit** or **Cancel**.

Waiting changes also appear in **Settings → AI → Activity** with a **Review** button, and show
who asked for them. The person who connected the app (including the owner) may confirm their own
app's sensitive action: that is confirming the AI, and the card records it as such. The store
owner, or anyone whose role can make that change, may also approve or cancel it. If the
approver's own role needs approval for that action, approving sends it to
**Settings → Approvals** for a different member instead. The change runs as the person who approves it: if
their role cannot do it, approving is refused, nothing changes, and the change keeps waiting for
someone who can. Activity records who approved it.

A waiting change expires after a while. Once it has, the row says **Expired** and approving it
does nothing; ask the app to suggest it again.

Files an app asks for, such as a shipping label or an invoice, come back as a download link that
works for 10 minutes.

## API tokens

Tokens are for scripts and servers, such as a script that syncs stock from your warehouse
software, and for AI apps that cannot sign in. People should sign in instead, so their own staff
permissions apply.

1. Under **API tokens**, click **Create token**.
2. Give it a name, tick only the areas it needs, and pick when it expires: 30 days, 90 days,
   1 year or never.
3. Click **Create token**. Copy the token **now**: it is shown only once, with the header and the
   Claude Code command ready to paste. Keep it in your server's secret settings, never in code.

A token acts as you, limited to the areas you ticked. Its changes happen at once with your role;
when your role needs approval for one, it waits in **Settings → Approvals** instead. A token can never refund or cancel, change staff or
billing, or change payment, domain or MCP & API settings; with the **Settings** area it can change
other settings, such as shipping or taxes. Click **Revoke** on a token to stop it.

## Activity

Click **View activity** to open everything apps and tokens did in the last 90 days, newest first,
grouped by day:

- **Reads:** an app read your data, such as "Claude read sales".
- **Changes:** something changed.
- **Waiting approval:** a suggested change you haven't approved yet.
- **Blocked:** a switch or a token's areas stopped something.

Each app and token can make up to 120 requests a minute, so one app can't slow your store.
Click **Export CSV** to download the whole log.
