# Waimers Commerce Docs

Documentation site for the Waimers Commerce Platform, built with [Nextra 4](https://nextra.site)
(`nextra` + `nextra-theme-docs`) on Next.js App Router. Two sections: the **merchant guide**
(for non-technical Indian shop owners) and **developer docs** (architecture, conventions,
guardrails, plugins SDK, data model, running locally, testing, backups, deployment).

Content lives in `content/` as MDX, organised by `_meta.ts` files (sidebar order and titles).
See `content/merchant-guide/` and `content/developer-docs/`.

Two developer-docs pages, [Architecture](content/developer-docs/building/architecture.mdx) and
[Backups](content/developer-docs/operations/backups.mdx), plus
[Plugins SDK](content/developer-docs/building/plugins.mdx), were moved here from `docs/*.md` (one
source of truth) — the old paths (`docs/architecture.md`, `docs/plugins.md`,
`docs/ops/backups.md`) are now short stubs pointing here.

## Running locally

```sh
bun install                 # from the repo root
bun run dev:docs            # http://localhost:3500
```

Port **3500** is this app's dev port. Never use 3100/3200/4100/3300 — those belong to the
storefront, admin, worker and other apps.

## Building

```sh
bun run build:docs          # from the repo root, or:
bun run --cwd apps/docs build
```

`next build` compiles the site, then the `postbuild` script runs
[Pagefind](https://pagefind.app) over the built HTML (`.next/server/app`) and writes a search
index to `public/_pagefind`. That index is what powers the `<Search />` box in the navbar in a
production build — it is not available in `next dev`, and it is not committed (regenerated by
every build; see `.gitignore`).

## Nextra version pin

`nextra` and `nextra-theme-docs` are pinned to **4.6.0** rather than the latest 4.6.1. Nextra
4.6.1's `<Layout>` throws `Invalid input: expected nonoptional, received undefined → at children`
on every render under `zod` 4.4+ (a rest-destructuring vs. required-field validation-order bug in
their release; see [nextra#5008](https://github.com/shuding/nextra/issues/5008) and
[nextra#5036](https://github.com/shuding/nextra/issues/5036)). This monorepo's `zod` (4.6.x, used
by `packages/api`/`apps/admin`) triggers it, so 4.6.0 — the last release before the regression —
is used until it's fixed upstream. Bump back to `^4.6.x` once that lands.

## Deployment

Not deployed yet; this is a placeholder plan, same shape as the rest of the platform
(see `docs/handoff.md` / [Deployment](content/developer-docs/operations/deployment.mdx)).

**Static export.** Nextra supports Next's static export (`output: 'export'`) and Pagefind
works against a static build too (index `out/_pagefind` instead of `.next/server/app`). That
is the preferred path for this site once it's ready to ship: no server needed, deployable to
Cloudflare Pages, GitHub Pages, or any static host, and it fits the "cheapest viable infra"
principle in `docs/architecture.md`. To switch:

1. Add `output: 'export'` to `next.config.mjs`'s Next.js options (the second argument to
   `withNextra`).
2. Change the `postbuild` script's `--site` flag to `out/_pagefind` (`next build` already
   writes the static export to `out/` when `output: 'export'` is set) — the `--output-path`
   should also point inside `out/` so Pagefind's assets ship with the exported site:
   `pagefind --site out --output-path out/_pagefind`.
3. Serve the `out/` directory from your static host.

**Normal Next.js server**, if a page ever needs a server feature this site doesn't have today
(none currently): run `bun run --cwd apps/docs start` behind the same reverse proxy/ECS setup
the other two Next apps will use once deployment is built.
