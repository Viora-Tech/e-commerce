# Admin bugs #295, #297, #299

- **#295 Discount amount** (`/orders/drafts/new`): the money inputs were controlled by `(paise / 100).toFixed(2)`, so clearing the box snapped it back to `0.00` and the next keystroke was appended to it. New `components/drafts/draft-money-input.tsx` keeps the typed text while focused (empty counts as 0) and tidies to two decimals on blur. Used for discount, shipping and each line price.
- **#297 "Input validation failed"** (`/products/[id]`): the product save is rejected by the API's zod schema when a stored value is over a limit (for example a search engine title over 70 characters, as imported products can have), and the form only showed the generic message. `validationIssuesOf` (`lib/api-errors.ts`) reads the issues and the form now says which field and what the limit is. Every product in the local dev DB passes the schema, so the exact failing value on the Waimers store is not confirmed from here.
- **#299 Collections strip** (`/products/collections`): added a previous arrow, both arrows disabled at the ends (no more wrap-around), horizontal trackpad scroll and touch swipe change page.

Not changed, same pattern: draft line quantity snaps to 1 when cleared; `settings/box-presets-fields.tsx` and automation step/trigger inputs coerce cleared numbers (`Number(e.target.value)`, `|| 1`).
