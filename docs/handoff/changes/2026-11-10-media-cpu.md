# Photo uploads no longer starve the storefront (#1471)

Incident 10 Nov 2026 09:08-09:25 UTC: a staff photo upload ran 30-74 s encodes on both cores,
both storefront health checks failed and one replica was killed; pages took 8 s.

- **One image at a time**: `QUEUE_LIMITS.mediaProcess` is 1 at once, 1 per store (was 3 and 2).
  `MEDIA_PROCESS_CONCURRENCY` / `MEDIA_PROCESS_PER_STORE` still override.
- **One core left free**: libvips gets `mediaCpus(cores, MEDIA_CPUS)` cores, every core but one
  unless `MEDIA_CPUS` is set (`apps/worker/src/media-limits.ts`). New env `MEDIA_CPUS` (worker,
  optional) in `packages/config/src/env.ts`, `deploy/env.production.example`, compose.
- **Cache**: a stream of media (soft) notifications no longer empties the store's page cache
  every minute: the bump waits until the images go quiet for 60 s, at most 10 minutes
  (`SOFT_MAX_WAIT_MS`, `apps/storefront/src/lib/cache-versions.ts`).
- Still to do (owner, Dokploy): cap the worker service at 1 CPU (developer docs Deployment ›
  CPU for the worker). Not done here: per-product cache refresh, slow-render log.
