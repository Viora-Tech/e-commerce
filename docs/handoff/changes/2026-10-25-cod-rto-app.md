# COD & RTO app (COD confirmation, RTO risk score, COD rule) + returns gaps

Branch `feat/cod-rto-app`. A built-in, free app (`cod-rto`) hosted in core like Pixels and Inbox, because it runs inside checkout's `placeOrder`, the notifications worker and the returns flow, which a plugin hook cannot reach. Manifest `packages/core/src/cod-rto/app.ts` (`@commerce/core/cod-rto-app`), wired in `commerce.config.ts`. Merchant guide: `apps/docs/content/merchant-guide/apps/cod-rto.mdx`.

## Migration `0172_cod_rto_app`

- `order.rto_risk` (jsonb `{ score, level, factors, scoredAt }`), `order.cod_verification` (`pending | confirmed | cancelled | unconfirmed`), `cod_verify_requested_at`, `cod_verified_at`, partial index `order_cod_verification_open`.
- `return_request.preferred_resolution` (`refund | exchange | store_credit`), `return_request.auto_approved`, `return_request_line.exchange_variant_id`.
- SECURITY DEFINER `stores_with_pending_cod_checks()` (+ `storesWithPendingCodChecks` in `@commerce/db`). No new tables.

## What it does

1. **COD confirmation** (`cod-rto/verification.ts`). At checkout a COD order (every one, or only medium/high risk) is stored `pending` and writes the new outbox event `order.cod_confirm_requested` → new template `cod_confirm` (email + WhatsApp, `actionUrl` = `/cod/<token>` on the store's domain, signed token purpose `cod-confirm`, 7 days). `codConfirmDelivery` sends it by the phone channel when the store has one and the order a phone, email otherwise, and nothing once the order no longer waits. Storefront page `apps/storefront/src/app/-s/[storeId]/cod/[token]` + `lib/cod-actions.ts`: Confirm, or Cancel (cancels the order via `cancelOrder` while nothing shipped). The worker's unpaid-expiry tick (`apps/worker/src/payments-expiry.ts`) runs `runCodConfirmationSweep`: past `flagAfterHours` (24) → `unconfirmed` + tag `cod-unconfirmed` + order note; auto-cancel after `autoCancelAfterHours` (48) only when turned on (off by default). Order card: "Confirmed by phone". WhatsApp needs an approved Meta template named `cod_confirm` with 5 body params (name, store, order number, total, link).
2. **RTO risk score** (`cod-rto/score.ts`, pure and tested): PIN code RTO rate from the store's own finished shipments (trusted after 5), the shopper's past RTOs / cancellations / deliveries (matched by order phone or email, guests included), address quality (too short, no digit = no house number), order value (> ₹5k, > ₹10k), first order; prepaid halves the score; thresholds medium 30 / high 60 in settings. Scored in a new `assessRisk` step of `placeOrder` (only when the app is installed), saved on `order.rto_risk`, tag `rto-risk-high`. "Score again" (`rescoreOrder`) for older orders. Shown on the order page (app `OrderCard`), the Risky orders page (tabs: medium+high, high, no answer, waiting, all) and as the tag in Orders.
3. **Rules**: `rules.hideCodForHighRisk` is enforced on the server (`CheckoutRuleViolation('cod_high_risk')`, storefront message `codHighRisk`). **Not done (later):** hiding COD in the checkout form before submit (the form would need the score for the typed PIN/phone; today the shopper sees the message on submit and picks online), and **partial prepaid** — only the setting and the pure `codPrepaidDuePaise` exist; checkout needs a split payment (part online now, rest at the door), which is a big checkout + payments change.
4. **Returns gaps** (compared with Shopify returns and Return Prime) — picked the three that save merchants the most work or money:
   - **Shopper-chosen exchanges** (Return Prime's headline feature; the form only said "say so in the note"): Settings → Returns → *Let customers ask for another size or colour*. The return form asks money back / store credit / another in-stock variant per line (`returns/preferences.ts`, `storefront/components/account/return-outcome.tsx`); `exchangeReturn` sends exactly what was picked; the admin return shows "Asked for" and defaults the resolve step to it. Keeps the sale instead of a refund.
   - **Auto-approve rules** (Shopify and Return Prime both have them): approve shopper requests for chosen reasons up to a value at once (`qualifiesForAutoApprove`, `return_request.auto_approved`). Saves a click per damaged/wrong-item return.
   - **Return reasons report** (`returns/report.ts`, app page *Return reasons*): returns by reason with units, value and share, top 10 products with their main reason, exchange and auto-approved counts.
   Skipped: QC grading beyond the existing condition check, return fees / restocking fees, and green returns (keep the item) — useful but less valuable than the three above.
5. **Admin**: `apps/admin/src/components/apps/cod-rto/*` (Overview with RTO rate overall / COD / prepaid, goods value back, COD answers, open orders by risk, worst PIN codes; Risky orders; Return reasons; Settings; order card), registered in `apps/admin/src/apps/registry.ts`. Copy `data/cod-rto.ts` + `data/hi/cod-rto.ts`; returns copy `returnRulesContent` (+ Hindi). API `codRto` router (`packages/api/src/routers/cod-rto.ts`).
