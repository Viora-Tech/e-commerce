# Profit you can trust: packing, delivery estimates, monthly expenses, floor profit

Design: `docs/superpowers/specs/2026-10-22-profit-design.md` (owner answers 1a and 2a recorded
there). Merchant docs: Analytics → Profit, Settings → Costs for profit, Settings → Shipping (box
cost), Settings → Monthly expenses (new page).

Open source: nothing adopted; this is our own profit formula on our own data. No new dependencies.

## What changed

- **Migration `0159_profit`** (next free after `0158_affiliates`; idempotent, journal `when` newest):
  `shipment.packing_cost_paise` + `shipment.box_preset_id` (packing snapshot at booking or hand
  packing), and `monthly_expense` (versions in a `series_id`, `starts_on` / `ends_on` first days of
  months, category check, `archived_at`; RLS via `apply_store_rls()`). Schema in
  `packages/db/src/finance-schema.ts`.
- **Core**
  - `order/profit-estimates.ts` (pure, PARCEL_COSTS): per parcel packing (snapshot, else box cost
    now, else flagged missing) and delivery (real charge per live consignment, else the highest
    real charge in 60 days for that courier and state, any courier when none is booked, else the
    store default ₹100). No estimate for cancelled-before-booking orders, cancelled parcels,
    gift-card-only parcels or orders without an address; a cancelled consignment keeps packing,
    not its charge.
  - `order/profit-parcels.ts`: loads parcels, consignments, boxes, states and the rate table for
    `profitFacts`; `packingSnapshot` for hand packing (`order/fulfil.ts`).
  - `order/profit.ts`: `ProfitInput.parcels` replaces `shipments`; `OrderProfit` gains
    `packingPaise`, `estimated` and flags `courierEstimated`, `packingEstimated`,
    `packingMissing`; `allocateProfit` shares packing too; `ProfitCostSettings.defaultDeliveryPaise`.
  - `shipping/settings.ts`: `BoxPreset.costPaise`; `shipping/parcel.ts` `parcelBoxPreset`;
    booking (`createShipmentForOrder`) snapshots the box (the one named, else the box whose size
    the packer picked, else the parcel's own).
  - `finance/monthly-expenses.ts` (pure, `@commerce/core/expenses`): month maths, prorating by
    counted days ("so far"), `planExpenseEdit` (in place, or split so past months keep theirs).
  - `finance/profit-summary.ts` (pure, `@commerce/core/profit-summary`): averages per order, per
    unit, by basket size 1/2/3+, estimated count, verdict (short by ₹X, about N more orders).
  - `finance/monthly-expense-service.ts`: list / create / update (versioned) / delete (archives
    the series).
- **API**: `monthlyExpenses.list|create|update|delete` (settings read/manage; MCP area
  `settings`, action docs regenerated). Profit by month adds Packing, Monthly expenses, Net
  profit, Orders still estimated (metric is now net profit); Profit by product adds profit per
  unit. `ReportResult.profit` carries the summary (`ProfitInsights`).
- **Admin**: order Profit card (Packing row, "estimated" on packing/delivery, Estimated tag,
  "at least", floor sentence, new notes); report summary card on the Profit reports
  (`analytics/profit-insights-card.tsx`); box cost field in Settings → Shipping; Default delivery
  cost card in Settings → Costs for profit; Settings → Monthly expenses page (table, add/edit
  dialog with "change from" month, delete confirm). Copy EN + HI.
