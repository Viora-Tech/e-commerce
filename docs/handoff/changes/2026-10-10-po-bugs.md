# Purchase order bug fixes

Branch `fix/po-bugs`. No migration.

- **Save and order in one step:** `purchaseOrders.save` takes `markOrdered`; the form's "Mark as ordered" sends one request, so a failure leaves no draft and a retry cannot make a second one.
- **Numbers:** PO and transfer numbers are taken under a per-store advisory lock (`nextDocumentNumber` in `core/inventory/levels.ts`), so concurrent creates queue instead of hitting the unique index.
- **Search:** `#PO12`, `PO12`, `po 12`, `#12`, `12` all find order 12.
- **Deleting a product on a PO or transfer** archives it (like order lines) instead of a foreign-key 500.
- **Ordered PO:** a save that changes lines, costs or destination returns `PO_LINES_LOCKED` (400) instead of silently dropping them; header edits still work.
- **Duplicate variants** on a PO or transfer are rejected by the input schemas (validation only, no unique index).
- **Cross-store:** `savePurchaseOrder` and `saveTransfer` check that every variant and location belongs to the store. Leak test maps `purchaseOrders.receive.lineId` to `purchase_order_line`.
- `get` for a missing id throws `NOT_FOUND`; the admin page turns it into `notFound()`. The list status filter uses `PURCHASE_ORDER_STATUSES`.

Pre-existing, not touched: `bun run lint` fails on `metafields-card.tsx` (useExhaustiveDependencies) on dev.
