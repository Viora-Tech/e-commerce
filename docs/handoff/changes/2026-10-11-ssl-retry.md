# SSL certificate retry for store addresses and custom domains (2026-10-11)

When a store address (`<slug>.<PLATFORM_STORE_DOMAIN>`) or custom domain is registered in Dokploy before its DNS exists, Let's Encrypt fails once (NXDOMAIN) and Traefik never retries, so the browser keeps Traefik's default certificate.

- Migration `0113_ssl_retry`: `store_domain.ssl_started_at`, `ssl_checked_at`, and `stores_with_certificate_checks()` (SECURITY DEFINER, for the worker).
- `packages/core/src/domains/certificate.ts` (TLS check, DNS check, backoff schedule, reasons) and `certificate-retry.ts` (`checkCertificate`, `runCertificateSweep`, `requestCertificateRetry`).
- Worker: `{domains}-certificate` repeat job every minute (only with `DOMAIN_PROVIDER=dns`). The route job accepts `reregister` and then re-checks after a pause.
- The platform route job no longer sets `ssl_status = 'active'` blindly; the sweep verifies it. Active rows are re-checked daily, which fixes rows wrongly marked active in production.
- Admin: the domain page shows Active / Waiting for DNS / Certificate failed with the reason and a **Retry certificate** button (`domains.retryCertificate`, `settings.manage`, one press per 2 minutes). The list shows the reason under failed addresses. EN + HI copy.
- Docs: merchant guide `settings/domains`, developer docs `custom-domains` ("Certificate checks and retries").
- No new env keys. Retries re-register in Dokploy only when the Dokploy keys are set; without them only the state and reason are recorded.
- Not built: a Retry button in the domains list (it is on the domain page); an email to the merchant when a certificate fails.
