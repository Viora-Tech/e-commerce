# GST phase 2 + 3: bill from the warehouse's GSTIN, invoices per GSTIN

**Branch** `feat/gst-phase-2-3`, from `main` after #223 (phase 1). **Migration
`0082_gst_phase_2_3`** (0081 is reserved for the theme import build, 0083 for the AI build; bump
if those land in another order and keep `when` increasing). No new tables: columns
`order.gst_registration_id` + `order.tax_origin`, `location.courier_pickup`, and
`gst_registration_id` on `invoice`, `invoice_sequence`, `invoice_period`; the function
`adopt_unassigned_gst_documents` and trigger `gst_registration_adopt_unassigned`; backfill of
every existing invoice, counter and return month to the store's default registration.

- **Tax origin (phase 3).** `placeOrder` charges CGST + SGST or IGST from the GSTIN of the
  location the goods sell from (`resolveTaxOrigin`, `packages/core/src/tax/origin.ts`,
  ORIGIN_FALLBACK: location's linked active GSTIN, else default GSTIN, else `store.address`).
  Prices are tax inclusive, so only the split changes. Snapshotted on the order and shown on
  the order page as "Billed from: Haryana · 06…". A variant still sells from one location;
  lines at different locations take the location with the most value (phase 4 splits them).
- **Invoices per GSTIN (phase 2).** Numbers unique per GSTIN per FY, counters per GSTIN +
  series + FY, return months filed/closed per GSTIN, GSTR-1 per GSTIN. The document's GSTIN
  is the order's (`orderIssuer`, `packages/plugin-gst-invoices/src/registration.ts`); credit
  notes and refund vouchers use the original's. Seller block: the app's own when it is that
  GSTIN's (single-GSTIN stores print exactly as before), else the registration's legal
  address and the business's PAN name. `{GST}` in series patterns prints the registration's
  invoice prefix or its state letters. `takeNumber` moved to `numbers.ts`.
- **Null registration** means a store with no GSTIN; `NULLS NOT DISTINCT` keeps one counter
  per series. The first default registration adopts those rows (trigger), so the series
  continues.
- **Courier pickup per location.** `location.courier_pickup` (opt-in on Settings → Locations)
  makes bookings and return pickups use the location's address and the courier's pickup name
  (`shipFromFor`, `packages/core/src/shipping/ship-from.ts`); otherwise
  `store.shipping.policy.warehouse` as before. Delhivery and Shiprocket take
  `pickupLocationName`. Pickup scheduling still uses the store-wide name.
- **Admin.** "GST number" picker on Queue, Invoices and Returns (hidden with one GSTIN);
  Billed from row on the order summary; Courier pickup column and card on Settings →
  Locations. Copy in `data/gst-invoices.ts` (`gstNumberPickerContent`), `data/business-gst.ts`,
  `data/orders.ts`, Hindi in `data/hi/`.
- **API.** `gstInvoices.gstNumbers`; optional `gstRegistrationId` on `list`, `queue.list`,
  `periods.*`, `seriesNext`, `gstr1` (omitted: default GSTIN for returns, every GSTIN for
  lists; a foreign id is refused by an RLS read); `businessGst.setLocationPickup`.
- **Core subpaths** `@commerce/core/tax-origin` and `@commerce/core/gst-registration-service`
  (server only) so the plugin does not pull the core barrel (and `@commerce/blocks`) into its
  typecheck.
- **Docs**: merchant guide (Business and GST, Locations, GST invoices "More than one GST
  number"), developer data model "Businesses and GST" tab.
- **Not here (phase 4)**: one order split across warehouses (fulfilment orders, an invoice per
  GSTIN), pickup scheduling per location, draft orders' tax origin (drafts still carry no GST
  split), Razorpay Route payouts.
- **CA questions** are listed in the PR: cancelled GSTIN on a credit note, mixed-location
  orders, `{GST}` fallback text, seller address source, and backfilling pre-0082 orders.
